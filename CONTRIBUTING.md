# Contributing

## Local Setup

This repo expects:

- Node `>=26.11.1 <27.0.0`
- The pnpm version pinned in [`package.json`](./package.json) `packageManager`
- Docker Desktop for local PostgreSQL development

Docker Desktop must be running before `pnpm dev`. The command starts and waits for local PostgreSQL, applies migrations, runs the idempotent seed, and then starts Vite. It refuses to prepare a hosted `DATABASE_URL`. Use `pnpm dev:app` only when the local database is already prepared and you intentionally want to start Vite directly.

The Node requirement and pnpm pin are declared in [`package.json`](./package.json).
[`.nvmrc`](./.nvmrc) pins Node 26.12.0, the tested baseline used by local version managers and CI. `package.json` retains support for `>=26.11.1 <27.0.0`; existing 26.11.1 installations remain supported. Node 26 is a Current release as of October 16, 2026; it is the chosen development/CI runtime, while deployed Workers use Cloudflare's runtime.

Node 26 no longer bundles Corepack. Install the reviewed Corepack release and enable pnpm before installing project dependencies:

```bash
npm install --global corepack@0.36.0
corepack enable pnpm
pnpm --version
```

Run the version check from the repository so Corepack selects the `packageManager` pin. If a Windows Node upgrade leaves `pnpm` pointing at a removed `corepack/dist/pnpm.js`, inspect `Get-Command pnpm -All` and `Get-Command corepack -All`. Regenerate the stale shims with `corepack enable pnpm --install-directory "<directory containing the stale pnpm launcher>"`; a protected installation directory may require an elevated terminal. Do not disable engine or integrity checks to work around launcher failures. CI installs pnpm with `pnpm/action-setup` and does not depend on bundled Corepack.

Copy [`.env.example`](./.env.example) to `.env` before running database commands. The local default uses Docker PostgreSQL on `localhost:55432`; do not point `.env` at Neon for daily development, seed testing, or destructive resets.

```bash
pnpm install
pnpm cf-typegen
pnpm dev
```

## Before Opening A PR

Run the same validation checks CI runs. Prepare the seeded local database and matching Playwright browsers first, as described in [Testing Notes](#testing-notes):

```bash
pnpm install --frozen-lockfile --ignore-scripts
pnpm audit signatures
pnpm audit --audit-level high
pnpm rebuild
pnpm version:check
pnpm check
pnpm typecheck
pnpm test
pnpm coverage
pnpm build
pnpm worker:check
pnpm test:e2e
pnpm test:transport
```

Release-relevant changes must update both [`package.json`](./package.json) `version` and [`CHANGELOG.md`](./CHANGELOG.md). See [`VERSIONING.md`](./VERSIONING.md) for the policy CI enforces.

If you want the shorter local baseline first, start with:

```bash
pnpm check
pnpm typecheck
pnpm test
pnpm build
```

## Testing Notes

- Unit tests use Vitest with [`vitest.config.ts`](./vitest.config.ts).
- Real PostgreSQL integrity tests require `RUN_DB_TESTS=true` and the local database; the dedicated CI database job runs them after migration and two seed passes. See [`AGENTS.md`](./AGENTS.md#query-helper-tests).
- E2E tests use Playwright with [`playwright.config.ts`](./playwright.config.ts).
- After building with `pnpm build`, run `pnpm test:transport` to verify unexpected database errors through the production RPC transport. This separate Chromium test requires a seeded local `kelsier_dev` database (`DATABASE_URL`, defaulting to `localhost:55432`) and an available loopback port 4191. It captures and aborts a creation request, then replays it against its own preview with an unreachable local database; no attempt is created. Hosted database URLs are refused. CI runs it after build and database preparation.
- Review UI through the running app with `pnpm dev`. Keep component behavior covered by Vitest and user journeys covered by Playwright.
- Playwright starts Vite directly instead of `pnpm dev` so the dev server shuts down cleanly on Windows.
- Before browser tests, start Docker PostgreSQL and apply migrations and seed data (`docker compose up -d`, `pnpm db:migrate`, `pnpm db:seed`) with the documented local database configuration. Direct Vite startup does not prepare the database. Install matching browser binaries with `pnpm exec playwright install chromium firefox webkit` after a Playwright upgrade.
- Local browser projects send distinct reserved `192.0.2.x` client addresses through `CF-Connecting-IP`, keeping their creation-rate buckets separate. Rate limits remain active. This simulates edge metadata only for local tests; it does not establish hosted edge behavior.
- Database migrations are generated by Drizzle. For schema changes, run `pnpm db:generate`, review the generated SQL under [`drizzle/migrations`](./drizzle/migrations), then validate locally with `pnpm db:migrate` and `pnpm db:seed`.
- Rerun `pnpm cf-typegen` after changing Cloudflare bindings, compatibility dates/flags, or Wrangler. Commit the generated diff; Wrangler upgrades can update runtime API declarations even when bindings are unchanged.
- pnpm dependency build-script approvals and install policy live in [`pnpm-workspace.yaml`](./pnpm-workspace.yaml). The workspace enforces approved builds and engines, a strict 24-hour release-age gate, fail-closed publication metadata, trust-downgrade rejection, and transitive exotic-source blocking.

## Formatting And Linting

- Biome is the formatter and linter for this repo.
- Run `pnpm format` to apply formatting changes.
- Run `pnpm check` to run Biome checks without writing changes.
- Tailwind CSS v4 directives are enabled in [`biome.json`](./biome.json), so keep that config in place unless the styling stack changes.

## Generated Files

- [`src/routeTree.gen.ts`](./src/routeTree.gen.ts) is generated by TanStack Router during the normal development and build workflows.
- [`worker-configuration.d.ts`](./worker-configuration.d.ts) is generated by Wrangler.
- [`drizzle/migrations`](./drizzle/migrations) is generated by Drizzle from schema changes and should be reviewed, not hand-authored casually.
- Do not hand-edit generated route tree output.

Generated files that should usually be committed:

- [`src/routeTree.gen.ts`](./src/routeTree.gen.ts)
- [`drizzle/migrations/*.sql`](./drizzle/migrations)
- [`drizzle/migrations/meta/*.json`](./drizzle/migrations/meta)
- [`worker-configuration.d.ts`](./worker-configuration.d.ts)
- [`pnpm-lock.yaml`](./pnpm-lock.yaml)

Local generated output that should not be committed includes `.claude/`, `.env`, `node_modules/`, `.pnpm-store/`, `dist/`, `.output/`, `.wrangler/`, `.tanstack/`, `coverage/`, `playwright-report/`, and `test-results/`.

Keep PR-specific plans, review reports, and speed comparisons untracked under `.wrangler/` or the ignored `docs/pr-*.md` pattern. Put lasting contributor guidance in the tracked documentation instead.

## Secrets

Never commit real credentials, tokens, Neon connection strings, Cloudflare secrets, R2 keys, npm tokens, or hosted database URLs.

Use [`.env.example`](./.env.example) for variable names and safe local defaults only. Use `.env` for local untracked values. Hosted secrets belong in the relevant platform secret manager, such as GitHub environments, Cloudflare settings, or the hosting provider secret store.

Before sharing logs, PR descriptions, screenshots, or generated docs, redact `DATABASE_URL`, `DATABASE_URL_POOLED`, R2 keys, Cloudflare tokens, Neon connection strings, and any access token.

## Deployment Notes

- Cloudflare Workers configuration lives in [`wrangler.jsonc`](./wrangler.jsonc).
- `pnpm preview` is the closest local deployment check before publishing to Cloudflare.
- `pnpm worker:check` performs a Wrangler deployment dry run without publishing.
- `pnpm deploy` builds the app and hands deployment to Wrangler.
- Mindphreak is staging and curiousphreak is dummy production. They temporarily share Neon, with staging alone running scheduled cleanup. Use the [account-specific deployment procedure](./docs/staging-operations.md#hosted-targets); do not deploy staging's Hyperdrive binding or cron unchanged to the second account. Public launch remains on hold.

## PR Guidance

- Prefer small PRs with a single focused change.
- Release-relevant PRs must update both [`package.json`](./package.json) version and [`CHANGELOG.md`](./CHANGELOG.md). CI enforces this with `pnpm version:check`.
- Maintainers can request an on-demand, review-only Claude pass by mentioning `@claude` in a pull request comment or review. Claude is not an automatic or required approver.
- If you touch routing, add or update at least one relevant test.
- If you change shared tooling or config, update [`README.md`](./README.md) and this file when the workflow changes.
- If you change dependencies, package-manager config, or CI install behavior, also review [`docs/security-hardening.md`](./docs/security-hardening.md).

## Local Database Setup

Local PostgreSQL runs through Docker Compose for daily development, migration checks, seed testing, and destructive resets. Neon remains the hosted database target for staging and production.

Prerequisite: Docker Desktop.

The local container exposes PostgreSQL on `localhost:55432` to avoid common Windows port reservations around `5432`.

```bash
# Start local PostgreSQL
docker compose up -d

# Stop local PostgreSQL
docker compose down

# Fully reset local PostgreSQL data
docker compose down -v

# Check running containers
docker ps

# Connect with psql inside the container
docker exec -it kelsier-postgres psql -U kelsier -d kelsier_dev

# Generate, apply, and seed the local database
pnpm db:generate
pnpm db:migrate
pnpm db:seed
```

## Tooling Notes

- Cloudflare Workers deployment is configured through [`wrangler.jsonc`](./wrangler.jsonc) and the Cloudflare Vite plugin in [`vite.config.ts`](./vite.config.ts).
- Node `24.x` is declared in [`package.json`](./package.json) and mirrored in [`.nvmrc`](./.nvmrc) for version managers.
- pnpm settings and build-script approvals are declared in [`pnpm-workspace.yaml`](./pnpm-workspace.yaml) through `allowBuilds`, `engineStrict`, and `strictDepBuilds`.
- [`worker-configuration.d.ts`](./worker-configuration.d.ts) is generated by Wrangler and should be refreshed with `pnpm cf-typegen` after adding or changing Cloudflare bindings.
- Vitest uses [`vitest.config.ts`](./vitest.config.ts) instead of sharing [`vite.config.ts`](./vite.config.ts). This avoids the full TanStack Start and Cloudflare runtime plugin stack keeping the unit test process open.
- Playwright starts Vite directly in [`playwright.config.ts`](./playwright.config.ts) instead of using `pnpm dev`. This is a Windows-friendly workaround so the dev server shuts down cleanly after E2E runs.
- Biome has Tailwind CSS directive parsing enabled in [`biome.json`](./biome.json) because Tailwind v4 syntax like `@theme` and `@plugin` is used in [`src/styles.css`](./src/styles.css).
- [`src/routeTree.gen.ts`](./src/routeTree.gen.ts) is generated by TanStack Router and is intentionally excluded from the normal editing and linting flow.
- Versioning uses [`package.json`](./package.json) as the source of truth. See [`VERSIONING.md`](./VERSIONING.md) and [`CHANGELOG.md`](./CHANGELOG.md).

## Cloudflare Workers

This repo is configured for Cloudflare Workers rather than static-only hosting.

Typical deploy flow:

```bash
pnpm install
pnpm cf-typegen
pnpm preview
pnpm deploy
```

If you add Cloudflare bindings later, update [`wrangler.jsonc`](./wrangler.jsonc) and rerun `pnpm cf-typegen`.

## CI

- `pnpm install --frozen-lockfile --ignore-scripts`
- `pnpm audit signatures`
- `pnpm rebuild`
- `pnpm version:check` on pull requests
- `pnpm check`
- `pnpm typecheck`
- `pnpm test`
- `pnpm coverage`
- `pnpm build`
- `pnpm test:e2e`
